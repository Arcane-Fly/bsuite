Purple and indigo are quarantined from semantics. Under protanopia, indigo and purple both collapse onto primary blue — purple measured ΔE 0.006 against primary, meaning the destructive colour and the primary action colour were the same swatch. They survive as decorative hues only.

Why the palette collapses the way it does. For a deuteranope the whole space folds onto a blue↔yellow axis plus lightness: blue #2563eb reads #5656eb, cyan reads #b0b0cb, but red #e31029 reads #83830f, green #22c55e reads #aaaa63 and amber #f5ae39 reads #c6c631 — three yellows separated only by lightness. So the design rule is one hue family on the cool side, lightness separation on the warm side, and never two cool hues in semantic opposition. Every pair in the shipped set now clears 0.162; the pairing it replaces scored 0.006.

Contract rules

What lint should enforce
Do — bind to roles

Components reference --role-* and the shadcn bridge. White-labelling mutates roles, so palette-bound components silently ignore tenant branding.

Don't — bind to palette

No --neon-*, no raw hex, rgb or hsl, no text-white or text-black in consumer code.

Do — separate error from primary

The invariant is separation, not a fixed hue. D2C's primary is blue, so error is red. Braden's primary is red, so Braden must solve its own error hue against the same rule.

Don't — put two cool hues in opposition

Blue, indigo and purple are one colour under protanopia. Never let two of them carry opposing meanings — that was the ΔE 0.006 defect this release fixes.

Do — tabular figures

Money, hours, rates, award codes and IDs use the mono face with font-variant-numeric: tabular-nums.

Don't — pure white or black

Lightness 1.0 and 0 are banned as tokens. In this system the words mean --white #f8f9fa and --black #0a0e1a — reference the token, never the literal. Inverse text is oklch(0.98 0.006 260); the deepest surface is 0.145.

Do — dot inside auth

The 16px dot field is the authenticated app-shell background across all five D2C apps. Use <DotPattern> from @bsuite/ui — never hand-rolled.

Don't — grid inside auth

The 32px grid is public/pre-auth marketing only, scoped to the hero wrapper. An app never renders both patterns in the same context.

Do — one gradient on text

Only --gradient-accent (blue → cyan), and only on marketing heroes.

Don't — glow in light mode

Light mode is shadows and hairlines. The cyber register belongs to dark mode only.
