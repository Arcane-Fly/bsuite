# Migration version-collision allowlist (bsuite#1707)
#
# All six submodules (crm7, conduit, R80.3, business-suite-unified, braden,
# throughput) plus the parent repo's own supabase/migrations/ deploy to the
# SAME shared Supabase project. supabase_migrations.schema_migrations is one
# table keyed on the 14-digit version string alone, so two scopes carrying a
# migration with the same version silently skip whichever one the CI
# applier (.github/workflows/supabase-migrate.yml) reaches SECOND.
#
# Format: one entry per line, `<14-digit version><whitespace><reason>`.
# Blank lines and lines starting with # are ignored. Every entry below was
# verified by diffing the colliding files (see scripts/check-migration-
# version-collisions.mjs and the bsuite#1707 investigation notes).
#
# Two reason categories:
#   intentional-duplicate  — the SAME migration content, deliberately
#                             checked into more than one scope (byte-for-byte
#                             identical). Applying it twice is a harmless
#                             no-op (idempotent CREATE ... IF NOT EXISTS /
#                             CREATE OR REPLACE style DDL), so the "second
#                             one is skipped" behaviour is actually fine here
#                             — there is nothing distinct to lose.
#   coincidental-timestamp — two GENUINELY DIFFERENT migrations that happen
#                             to share a timestamp by chance (independent
#                             authors, same minute). These are real risk: if
#                             the file that is skipped is the one carrying
#                             the collision, its DDL never runs in
#                             production. They are allowlisted here only
#                             because they are historical (predate this gate)
#                             and have been manually verified as already
#                             applied in the live database; do NOT use this
#                             pattern as a template for new migrations — pick
#                             an unused timestamp instead.
