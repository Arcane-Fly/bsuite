# SECURITY DEFINER functions in schema `public` that may be executed by `anon`.
#
# Read by scripts/supabase/check-secdef-grants.mjs (checks 1 and 2).
#
# FORMAT
#   <function>(<argument TYPES, comma separated, no spaces>)   # why anon needs it
#
# Example — a function declared in its migration as
#
#     CREATE FUNCTION public.r7_redeem_talent_pool_consent(p_token text) ...
#
# is written here as
#
#     r7_redeem_talent_pool_consent(text)      # ...reason...
#
# No schema prefix. No parameter names. Types only.
#
# The signature is rendered by the checker as
#
#   proname || '(' || string_agg(format_type(t, NULL), ',') || ')'
#     over unnest(proargtypes)
#
# and it is NEITHER of the two obvious spellings, because both are wrong here:
#
#   * `oid::regprocedure::text` gains a `public.` prefix whenever search_path
#     does not contain public. An entry written without it then matches nothing —
#     and on an allowlist, "matches nothing" means "everything is unlisted", so
#     the whole estate fails at once.
#
#   * `pg_get_function_identity_arguments(oid)` includes PARAMETER NAMES:
#     `r7_redeem_talent_pool_consent(p_token text)`, not `(text)`. That is not a
#     hypothetical — it is what this gate did on its first real run (bsuite run
#     33727868315), reporting four allowlisted functions as unlisted while
#     simultaneously reporting the same four as "allowlisted but not present":
#     the two halves of one mismatch, printed six lines apart. The local fixture
#     could not catch it, because functions created as `f(text)` have no
#     parameter names to include.
#
# Building the list from proargtypes has neither failure mode, and the checked-in
# self-test now plants a function with named parameters so this rendering path is
# exercised in CI rather than by production data.
#
# A line without a `#` reason is a HARD FAILURE, not a warning. An allowlist
# entry whose justification is missing is indistinguishable from one nobody
# reviewed, and this file's whole value is that every line was argued for once.
#
# THE RULE THIS FILE ENCODES
# ──────────────────────────
# Anon reachability is legitimate only for the token-redemption / consent /
# signing class: a function reached from an unauthenticated portal route, whose
# ONLY key is a high-entropy token the caller must already possess, and which
# fails closed when that token is absent, expired or already redeemed.
#
# Every entry below carries a NAMED `anon` grant preceded by an explicit
# `REVOKE EXECUTE ... FROM PUBLIC` in its own migration (the estate's template is
# crm7 supabase/migrations/archive/20260812070000_portal_invite_mint_accept.sql
# lines 294-296). Named-and-revoked is the shape that belongs here. Reachable by
# PUBLIC is never allowed — see the PENDING section at the foot of this file.
#
# Census taken live against tuybltdrdefjblnplpqo on 2026-09-03: exactly 8
# SECURITY DEFINER functions in `public` were anon-executable. The 7 below hold a
# named anon grant and NO PUBLIC grant. The 8th, is_developer_admin(), was the
# inverse — PUBLIC grant, no named anon grant — and is being revoked.
