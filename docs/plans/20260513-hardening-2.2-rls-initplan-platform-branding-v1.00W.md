## Goal

Wrap `auth.uid()` in `(SELECT auth.uid())` for every RLS policy expression on
`public.platform_branding` so Postgres can evaluate the auth function as a
single initplan before the row loop, rather than re-evaluating it once per row.

This is step 1 of the 25-policy Phase 2.2 epic. The parent bsuite repo is
responsible for the `platform_branding` table; the remaining tables are owned
by the crm7, conduit, and other submodule repos.

## Background

The Supabase performance advisor `auth_rls_initplan` flags policies where
`auth.uid()` / `auth.jwt()` appears directly in the policy `qual` or
`with_check` expression. PostgreSQL's query planner can hoist a function call
wrapped as a scalar subquery — `(SELECT auth.uid())` — into an "initplan": a
node executed once before the main row loop. Without the wrapper, even a STABLE
function may be called once per row in some query plans, causing O(n) overhead
on tables with many rows.

Wrapping with `(SELECT …)` is the canonical fix per:

- Supabase performance advisor docs
- `supabase-postgres-best-practices` `query-` category
- `AUTH_CANONICAL.md` RLS patterns

## Affected policies

| Policy | Command | Expression | Change |
|--------|---------|-----------|--------|
| `platform_branding_insert` | INSERT | WITH CHECK | `auth.uid()` → `(SELECT auth.uid())` |
| `platform_branding_update` | UPDATE | USING | `auth.uid()` → `(SELECT auth.uid())` |
| `platform_branding_update` | UPDATE | WITH CHECK | `auth.uid()` → `(SELECT auth.uid())` |

Policies not changed (no auth function in predicate):

- `platform_branding_select` — `USING (true)`
- `platform_branding_select_anon` — `USING (true)`
- `platform_branding_delete` — `USING (false)`
