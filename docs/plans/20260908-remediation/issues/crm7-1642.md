**Source:** operator full-spectrum review, 2026-08-11 (Tier 2.5).

## Finding

| Marker | Count |
|---|---|
| `any` | 624 |
| `@ts-expect-error` | **256** |
| non-null assertion (`!`) | 126 |

Much of the `any` is the generated `src/types/supabase.ts` (21,646 lines) and is not worth chasing.

**The 256 `@ts-expect-error` are the interesting number.** Each one is a *real type error that was suppressed*. Unlike `any`, which is often laziness, `@ts-expect-error` marks a place where the compiler objected and someone overrode it — so each is either a genuine library-typing gap, or a bug wearing a comment.

## Why this is worth a pass, not just a note

This session found two crashes caused by a **hand-written type that disagreed with the database** (`DocumentTemplate`/`DocumentRecord`, crm7#1595). The compiler could not help, because the wrong shape was asserted with confidence. `@ts-expect-error` is the same failure mode made explicit: the type system knows something is wrong and has been told to be quiet.

## Approach

1. **Triage, do not bulk-fix.** Classify each: (a) upstream typing gap — keep, with a comment naming the library and version, (b) genuinely unsafe — fix, (c) stale — the error no longer occurs, so the directive itself is now an error under `noUnusedTsExpectError`. **Start by finding (c)** — those are free, and TypeScript will report them for you.
2. **Ratchet the rest.** This repo already ratchets ESLint (`eslint-baseline.json`) and pure-colour counts (`theme-c1-baseline.txt`). The same mechanism applies: record today's count, fail on an increase. That stops the number growing while the backlog is worked.
3. A bare `@ts-expect-error` with no description should be a lint error going forward — `@typescript-eslint/ban-ts-comment` supports `descriptionFormat`. A suppression with no reason is unreviewable.

## Related, same family
- 126 non-null assertions: each asserts the compiler is wrong about nullability. In a codebase where a hand-written type was wrong about a whole table, that assumption deserves checking.
- Over-memoization (Tier 2.6): 1,303 `useMemo`/`useCallback` with React Compiler enabled, most now redundant. Low priority — stop adding new ones, note it in CONTRIBUTING.
