# `/portal/worker` has no shareable application link for job ads and no SEEK/board posting or profile-scrape import

Snapshot updatedAt: 2026-08-26T12:22:01Z. Open at capture; re-read live.

Operator observed: `/portal/worker` should generate a link that can be placed in a job advertisement and carry a candidate into an application — or post directly to SEEK and equivalents with profile scraping and application import.

**Route/surface:** `/portal/worker`

Directive: D-80 (2026-08-13)

## Acceptance criteria
- `/portal/worker` (or its underlying record) can generate a shareable application link suitable for pasting into a job ad, which lands an external candidate on an application form pre-associated with the right role/vacancy.
- A path exists (even if phase 1 is manual-assisted) to post the same vacancy to SEEK or equivalent job boards.
- Where a candidate profile is imported (via scrape or board API), the resulting application is created as a real application record linked to the candidate — not a manual re-entry.

## Mandatory before merge
- **Validation loop:** §9.1 output-equivalence — an application created via the generated link/import must be a real application record indistinguishable from one entered manually.
- **Equivalence target:** A candidate arriving via the generated link, or imported from SEEK, produces the same application record shape as one entered through the standard application form.
