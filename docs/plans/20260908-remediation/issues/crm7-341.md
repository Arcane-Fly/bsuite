# refactor(crm7): unify schema-builder permissions around canEditPlatformSchema / canEditTenantViews

https://github.com/GaryOcean428/crm7/issues/341

Snapshot updatedAt: 2026-08-24T03:27:51Z. Open at capture; re-read live.

## Context

The CRM7 schema-builder / AI-tools layer currently uses ad-hoc `manage_system` permission checks (heavily in `crm7/src/lib/ai/tools/ui-builder-tools.ts`). The BSU schema-builder audit recommends unifying all schema-authoring permissions around two named helpers:

- `canEditPlatformSchema()` — true for platform admins (editing system-owned schemas)
- `canEditTenantViews()` — true for tenant admins (editing their own tenant views/fields)

Goal: create these two helpers, replace ad-hoc `manage_system` / `subscription.bypass` gates with them.

Ref: parent ledger Priority 4 — schema-builder unification.

## Canonical sources

- `crm7/src/lib/ai/tools/ui-builder-tools.ts` — existing ad-hoc `manage_system` checks
- `crm7/src/services/schemaBuilderService.ts` — the service these permissions guard
- `crm7/src/contexts/AuthContext.tsx` or wherever current user + roles live
- Existing permission/role helpers in `crm7/src/lib/auth/` or `crm7/src/lib/permissions/` (check first — reuse if present)

## Scope

1. Create `crm7/src/lib/permissions/schemaBuilderPermissions.ts` exporting:
   ```ts
   export function canEditPlatformSchema(user: CurrentUser | null): boolean
   export function canEditTenantViews(user: CurrentUser | null, tenantId: string | null): boolean
   ```
2. `canEditPlatformSchema` must return true only for users with platform-admin role (e.g. `is_platform_admin` claim or role name). Do NOT base this on `subscription.bypass`.
3. `canEditTenantViews` must return true for users who are an admin of the given tenant.
4. Add unit tests for both functions in `crm7/src/lib/permissions/__tests__/schemaBuilderPermissions.test.ts` covering: null user, tenant admin, platform admin, non-admin, wrong tenant, etc.
5. Grep call sites: `rg -n 'manage_system|subscription\.bypass' crm7/src/` — replace each site with the appropriate helper.
6. Do **not** change the underlying AuthContext shape — only add helpers + use them.

## Allowed paths (hard whitelist)
