# The unsaved-work register accepts a different form's reset as proof

https://github.com/GaryOcean428/crm7/issues/2461

Snapshot updatedAt: 2026-09-05T14:53:43Z. Open at capture; re-read live.

Found by the PI-run enforcer while gating #2448, by biting the guard itself rather than the code the guard protects. Not blocking — the shipped code is correct. This is about what the assertion can actually see.

## The imprecision

The unsaved-work register asserts that every registration gated on an `open`-style flag is backed by a reset. The `resetBesideOpen` clause looks for a bare `reset\(` within 400 characters of `set<Flag>(true)`.

It does not check *whose* reset it found.

`integrations.tsx` is the first file with several forms to carry gated registrations, and it exposes this immediately. Removing **every** `apiForm.reset()` from the open paths still passes 128 of 128, because the span that satisfies the clause is `documentServiceForm.reset({…})` in `handleEditIntegration` — a different form's reset, sitting close enough in the file to count.

The enforcer printed the satisfying span rather than inferring it, so this is measured rather than reasoned.

## Why it matters

The clause exists to catch exactly the defect this PR closed: a registration gated on a flag whose panel does not reset, so a cancelled draft stays declared and unreachable. A proximity match that any nearby reset satisfies will report that as backed while it is not, and it will do so most reliably in the multi-form files where the mistake is easiest to make.

## Fix

Bind the pattern to the form the registration names: `${form}\.reset\(` rather than `reset\(`. One token.

## Acceptance

Removing a given form's resets from its open paths fails the assertion for that registration and no other. A nearby unrelated form's reset does not satisfy it. Both directions asserted, so the fix cannot be achieved by making the clause never match.

## Related, already recorded

The same assertion documents a companion false negative in its own comment: `reset(getValues())` re-baselines while keeping every value, so a dialog using it satisfies the guard and still hands back a cancelled draft. Same character — the clause tests for the presence of a call rather than for what the call does. Worth fixing together and worth one sentence in the header saying what the clause does and does not establish.
