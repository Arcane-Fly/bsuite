## Coverage gap: no WebKit/Safari target in CI — a whole bug class is invisible

The sidebar bug (#1171 / operator's "Bug 1") is a **WebKit-only** failure: a `position: fixed` sidebar container escapes an ancestor's `overflow: hidden` on Chromium/Firefox (per CSS spec, absent a containing-block ancestor), but WebKit-family engines don't reliably honour that escape — so the nav footer clips only on Safari/iPad. This class of bug is **invisible to Chromium-only CI**.

A second WebKit-specific mechanism compounds it: **pre-15.4 Safari drops `h-svh` entirely** (the fixed sidebar container falls back to `height: auto`), which can also clip/unbound the sidebar independently of the overflow question.

### Evidence
- The #1171 harness could NOT reproduce Bug 1 in Chromium even with the old `overflow-hidden` present — the mechanism requires WebKit.
- `crm7/playwright.config.ts` references a webkit device conceptually, but the WebKit browser isn't installed / run in CI (verified: no WebKit pass exists).

### Why it matters
macOS Safari + iPad Safari are a real share of AU SME users (the "short laptop / split-screen" reports that surfaced Bug 1 are consistent with macOS). Without a WebKit lane, `position:fixed`/`svh`/`overflow` regressions ship silently.

### Fix
1. Install + run Playwright's `webkit` project in CI (at least a smoke lane on the app shell at short viewports + 150% zoom).
2. Add a shell-layout regression test (sidebar footer reachable, no document double-scroll) that runs on webkit specifically.
3. Once a WebKit target exists, #1171's fix can be **proven** (currently it's a plausible-mechanism mitigation, Chromium-verified for no-regression only).

### Acceptance criteria
- [ ] CI runs a Playwright WebKit lane on the authed shell
- [ ] A test asserts the sidebar footer is reachable at a short viewport on WebKit
- [ ] #1171's efficacy confirmed (or the real mechanism identified) on WebKit
