Operator requirements, 2026-08-02. Filing as one spec because they share a substrate: **the training catalogue is currently qualifications-only, national-only, and has no RTO scope data.**

Each item below is marked by what actually blocks it — I measured the data before assessing, and the answers were not what the column names suggest.

### The scope blocker, stated precisely

`training_providers.qualification_scope_global` is `jsonb DEFAULT '[]'`, present on all 8,119 rows, and **every single one is still `[]`**:

```sql
SELECT count(*) FROM training_providers WHERE jsonb_array_length(qualification_scope_global) > 0;
-- 0
```

So the column exists and the data does not. **Nothing can filter RTOs by qualification today.**

The source does exist: `_shared/tga-soap.ts` already sends `<ShowScope>true</ShowScope>` on `OrganisationService.GetDetails`. Nothing consumes the result.

---

## 1. Qualification ↔ RTO mutual filtering — BLOCKED ON DATA

*Pick a qualification → only RTOs that deliver it. Pick an RTO → only qualifications it delivers.*

Needs, in order:

1. **A scope loader.** Per-RTO `GetDetails` with `ShowScope`, 8,119 calls at TGA's fair-use rate — this is a batched background job, not a sync. Design it with the same `<Count>`-style completeness gate as `tga-sync`, or it will silently half-load.
2. **A real link table, not the jsonb column.** `training_provider_qualifications (training_provider_id, qualification_code, status, effective_from/to)` with indexes both ways. Bidirectional filtering over a jsonb array across 8,119 rows will not hold up, and scope has *dates* — an RTO's registration for a qualification starts and ends.
3. Only then the UI, which is the small part.

**Open question for you:** should a qualification with **no** scope data yet show *all* RTOs, or *none*? "None" is safer but makes the field unusable until the loader completes; "all" is today's behaviour and silently wrong. My inclination is all-with-a-warning until the loader lands, then flip.

## 2. Show/hide superseded + grandfathered — SHIPPED (partly)

Tickbox added, default OFF. Superseded and Deleted are hidden unless asked for; teach-out is preserved because it is a toggle, not an exclusion.

**"Grandfathered" is not built, deliberately.** TGA's feed has exactly three states — Current, Superseded, Deleted — and no grandfathered value, so there is nothing to filter on. Either it maps to Superseded, or it is a state-authority concept outside the national register. **Which is it?** Guessing wrong hides a live qualification behind a default-off filter.

## 3. Units treated like qualifications — NOT BUILT

`units_of_competency` has 160 rows against TGA's ~75,152. The whole unit side is demo data.

This is the same job I just did for qualifications, and the measurements carry over: `IncludeUnit=true` on `SearchByModifiedDate` returns 80,392 components of which 75,152 are units, and `PageIndex`/`PageSize`/`FromDate` are all inert. So a unit sweep is one ~48 MB call — it will **not** survive the current 60s SOAP timeout and needs a different shape (likely per-training-package).

Units also need their own currency columns and the same "show retired" treatment.

## 4. Unit import beyond the qualification's own set — NOT BUILT

Including **electives imported from other qualifications**, which some packaging rules explicitly permit.

Needs the real unit grid first: TGA `GetDetails` returns `UnitGrid` with `IsMandatory` per entry (confirmed — I read the payload for `CPC30220`: 359 `UnitGridEntry` elements across 6 releases). `qualification_units` at 119 rows does not have this.

## 5. Core units auto-added — NOT BUILT

Falls out of #4: `IsMandatory` from the unit grid drives it. Cheap once the grid is real, impossible before.

## 6. "Import every time" template — ENABLING MODEL ONLY, per your instruction

Same RTO + same qualification + apprentices starting around the same time ⇒ near-identical training plans. You said build the functionality to enable it, not the UX.

Enabling shape:

- `training_plan_templates (tenant_id, training_provider_id, qualification_id, name, is_default)` + `training_plan_template_units`
- a "save this plan as the template for this RTO+qualification" write path
- a "seed from template" read path on training-plan creation

The UX (the actual tickbox, defaults, per-user preference) stays out until you call it.

## 7. Custom / state-accredited qualifications and skill sets — NOT BUILT

STAs accredit state qualifications and skill sets that mix **national units + state-accredited units + learning materials**. This breaks two current assumptions:

- `catalog.qualifications` is TGA-shaped and TGA-loaded, with a loader contract that says only `ComponentType=Qualification` belongs. A state-accredited qualification has no TGA code and would be **overwritten or orphaned by the next sync** — the sweep upserts on `code`.
- There is no skill-set entity at all.

So this needs an explicit **origin discriminator** (`national_tga` / `state_accredited` / `custom`) and the loader constrained to its own origin, or custom rows will not survive. `qualification_sta_status` (0 rows) may be the intended hook — it exists but was never used.

## 8. High-risk licences modelled as skill sets — NOT BUILT

Follows #7. HRW licences (forklift, EWP, rigging…) are structurally skill-set-like: small fixed unit sets, separate currency/expiry, and a licence number per person rather than a qualification. Worth confirming whether they should be the *same* entity as a skill set or a sibling — the expiry/renewal behaviour differs.

---

## Suggested order

1. **Unit catalogue sweep** (#3) — unblocks #4 and #5, and is a near-copy of the qualification work
2. **RTO scope loader + link table** (#1) — unblocks the mutual filtering
3. **Origin discriminator + skill sets** (#7, #8) — schema change, best done before the catalogue grows
4. **Template model** (#6) — enabling only
5. UI last, once each has real data behind it

Nothing here should be built UI-first. Every one of these has failed the same way before: the surface ships, the data never arrives, and the empty state reads as "none exist" rather than "never loaded".
