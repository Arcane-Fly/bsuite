# Make stop-acting and pin-selection atomic in switchTenant

https://github.com/GaryOcean428/crm7/issues/2427

Snapshot updatedAt: 2026-09-04T13:53:21Z. Open at capture; re-read live.

`switchTenant`'s own-membership branch does two writes that must succeed or fail together:

1. `platform_admin_stop_acting()` — clears any live acting-as row.
2. `set_current_tenant(p_tenant_id)` — pins the selection in `profiles.current_tenant_id`.

Between them the caller is in a state neither of them intended: the scope has moved and the
selection has not. crm7#2425 handles that with a compensating path — `scopeChanged: true`, and
the caller reloads into whatever scope now applies — which is correct and is not the same thing
as the two writes being atomic.

**Why the interim was chosen.** The atomic version is a new `SECURITY DEFINER` function on
`platform_admin_acting_as`, and that did not belong in a branch already carrying the crm7#2398
promotion. The compensating path is the smaller change and closes the observed defect.

**What atomic would look like.** One RPC that stops acting and sets the current tenant in a
single transaction, so a failure leaves neither applied. It also removes the reload-on-partial
behaviour, since there would be no partial state to reload into.

**Why this ticket exists rather than a comment.** The interim is only correct while somebody
remembers it is an interim. Filed so it does not become permanent by silence.

Raised from the crm7#2398 promotion review. See crm7#2425 for the compensating fix and its tests.
