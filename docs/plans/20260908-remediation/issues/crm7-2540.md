# WHS Training Management heading bleeds off its card at 390px, and collides with Create Module button

https://github.com/GaryOcean428/crm7/issues/2540

Snapshot updatedAt: 2026-09-07T10:06:15Z. Open at capture; re-read live.

Found during the phase-3 visual close-out inspection of crm7#2528/#2530/#2532/#2518 on d.crm.crm7.app @ `2f67dc0` (2026-09-07T09:30:57Z), while inspecting `/whs/training` (crm7#2532's surface). Reproducible in **both themes**, so it is a layout bug, not a colour one.

## What's wrong

`src/pages/whs/training/index.tsx` lines 14-24: the page header

```tsx
<div className="mb-6 flex items-center justify-between">
  <div className="flex items-center space-x-4">
    <BackButton to="/whs" label="Back to WHS" />
    <div>
      <h1 className="text-3xl font-bold flex items-center">
        <GraduationCap className="h-8 w-8 mr-3 text-success-text" />
        WHS Training Management
      </h1>
      <p className="text-muted-foreground mt-1">...</p>
    </div>
  </div>
</div>
```

has no width constraint (no `flex-1 min-w-0`, no `truncate`, no wrap) on the `h1` or its
wrapping `div`. At 390px viewport width the CanvasCard is ~320px wide; the h1 renders at its
natural `text-3xl` width (measured 229px box positioned at x=207) and its right edge lands at
x≈435 — 45px past the 390px viewport. Because the clip happens on an ancestor with
`overflow: hidden` rather than at the document root, `document.documentElement.scrollWidth`
stays 390 (no horizontal scrollbar), so a page-level overflow check does not catch it — only
looking at the rendered card does.

Second, unrelated-looking but same root cause (no width budget on the header row): the
`Training Module Management` `CardTitle` in the second card sits directly behind the
`+ Create Module` button — the button is absolutely/flex-positioned over the heading text
rather than the row wrapping.

## Evidence

- `WHS Traini[ng] Manageme[nt]` truncated illegibly on the right, both themes, 390px.
- `Training Module Management` heading text visually overlapped by the `+ Create Module`
  button, both themes, 390px.
- Confirmed via `getBoundingClientRect()`: heading `right: 435.6` against `innerWidth: 390`,
  while `document.documentElement.scrollWidth === clientWidth === 390` (no page-level
  overflow signal).
- Not a colour/theme issue — identical in light and dark.

## Scope

This is bespoke JSX in this one file, not a shared component, so it is not confirmed to be a
wider class — but the pattern (`h1.flex.items-center` with an icon, no width constraint,
inside a fixed-width `CanvasCard`) is a plausible template for other hand-built page headers
and was not swept across the estate as part of this finding. Worth a `grep -rn
'text-3xl font-bold flex items-center'` pass before assuming it's isolated.

Filing separately per the visual-inspection protocol (different defect class, not the one this
