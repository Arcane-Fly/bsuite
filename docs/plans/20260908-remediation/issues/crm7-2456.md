# Saving one settings section silently destroys unsaved edits in the other three

https://github.com/GaryOcean428/crm7/issues/2456

Snapshot updatedAt: 2026-09-05T14:04:06Z. Open at capture; re-read live.

Found by the PI-run enforcer while gating #2448. Pre-existing and byte-identical before that PR, so it is not caused by it.

## What a user loses

Open settings configuration. Start editing the Email section. Before finishing, save the General section. The Email draft is silently destroyed, and it is marked clean on the way out, so nothing warns and nothing offers it back.

## Cause

Saving any one section invalidates the `['tenant-settings']` query. The hydration effect then re-runs and resets **all four** page-level forms, not just the one that was saved. The other three are re-baselined to the freshly fetched values, so any unsaved typing in them is both discarded and reported as clean.

## Why it matters beyond the immediate loss

The unsaved-work register treats these settings sections as retained work: the reasoning is that a settings tab keeps its edits when the tab changes or a panel collapses, so the draft is still there and still losable, and therefore must be declared. That reasoning is correct about tab changes. This defect holes the same premise from a different direction, because there is one ordinary action on the page that does not retain the work at all.

The registration is still right. A user who types into Email and reloads should be asked. But a user who types into Email and saves General should not lose it, and today they do.

## Fix direction

Reset only the form whose section was saved, or re-baseline the others without clobbering dirty fields. The general shape is that a refetch triggered by one section should not be allowed to overwrite in-progress edits in another.

## Acceptance

Type into one section, save a different one, and the first section keeps both its text and its dirty state. Then reload and confirm the unsaved-work prompt still fires for it, so the fix does not achieve retention by quietly dropping the registration.

Tests must fail against the current effect. A test that saves the only dirty section passes today.
