## The gap, ranked by consequence

| Area | Coverage | If it breaks silently |
|---|---|---|
| **AVETMISS** | ~12% (2/17) | A wrong NAT file is lodged with NCVER. Annual statutory obligation for a GTO. |
| **Xero adapter** | **0%** (1,153 LOC) | Invoices, payments and credit notes desync from the accounting ledger. |
| Compliance lib | ~20% | Compliance state reported wrongly to a regulator or a host. |
| Payroll | ~40% | Wage error. |
| Awards | ~40% | Wrong penalty/allowance — an underpayment. |

The repo's own standard (`CLAUDE.md`, `AGENTS.md`) is **70% for critical paths**. These are not adjacent to the critical path; they *are* it. AVETMISS and Xero are the two places where a silent defect stops being a bug and becomes an incident with a regulator or an accountant.

## Why "0% on the Xero adapter" is worse than it sounds

Untested integration code fails **quietly and late**: a field mapping drifts, a sync reports success, and the discrepancy surfaces at reconciliation weeks later, by which time the wrong number is in someone's books. There is already a known Xero UI-wiring gap (#1320) — the adapter beneath it has never been exercised by a test.

## Approach — do not chase the percentage

A coverage number is satisfiable without testing anything that matters. Target the **decisions**, not the lines:

1. **AVETMISS**: the NAT file *contents*. Fixture in → expected NAT rows out, per file type, including the demographic edge cases AVETMISS is fussy about. Validation-failure paths matter as much as the happy path — a silently-dropped record is the failure mode.
2. **Xero**: the adapter's mapping in both directions, plus the error/retry paths. Mock at the HTTP boundary, not at the adapter's own interface, or the test asserts the mock.
3. **Awards/payroll**: reconcile against the **published pay guide**, not a test-local re-derivation of the same logic — see `biz-au-award-modelling`. A test that re-implements the engine's arithmetic proves only that the arithmetic is self-consistent.

## Then hold the line

Wire a coverage threshold in CI (**see the CI wire-up issue** — `test:coverage` exists and no threshold is enforced), scoped to these paths first rather than globally, so the number cannot slide back.
