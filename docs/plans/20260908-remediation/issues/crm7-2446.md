# A hanging test is not bounded by testTimeout: a render loop ran 120s to a hard kill; the job needs its own timeout

https://github.com/GaryOcean428/crm7/issues/2446

Snapshot updatedAt: 2026-09-05T11:49:39Z. Open at capture; re-read live.

Measured by the PI-run enforcer on crm7#2433: a test probe ran **120 seconds to a hard kill** despite `testTimeout: 30000` in the vitest config. A hang inside a render loop does not yield to the per-test timeout, so the value that is supposed to bound a stuck test does not bound this one.

This has now bitten three times in one day on the same repository, each time from the same family — a mock whose object identity changes per render against a component that depends on a stable callback, producing an infinite render loop that presents as a slow test rather than a failing one. Two of the three were abandoned and their files deleted, correctly, because a hanging test in the tree is worse than the gap it was meant to close: in CI it reads as a timeout rather than a regression.

What is missing is the outer bound. `testTimeout` governs an individual test's own promise; it does not stop a synchronous render loop. The job needs a **job-level timeout** (`timeout-minutes` on the step or job in `ci.yml`) so a hang fails fast and loudly with a message that names the file, instead of consuming the runner until the platform kills it.

Worth pairing with a note in the testing guidance: when mocking a dependency that a component passes to `useEffect` deps, hoist the mock to a module-level singleton. The failure mode of getting that wrong is not a wrong assertion, it is a hang.
