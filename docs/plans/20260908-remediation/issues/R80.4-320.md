# V-C8: two free-text inputs on / name canonical entities with no FK-backed selector (8/8 cells)

https://github.com/GaryOcean428/R80.4/issues/320

Snapshot updatedAt: 2026-09-06T13:47:45Z. Open at capture; re-read live.

`visual-probe.js` class **V-C8 `freeTextEntity`**, production `r8.crm7.app` @ `10187e2`,
`/`, **both themes, all four widths — 8 of 8 cells**, 2 findings each.

```
FAIL: free-text input for a field that names a canonical entity — must be an FK-backed selector
  sel  input.w-full.text-xs.rounded
  sel  input.w-full.rounded.px-2
```

The probe flags a text input whose label names a canonical entity (Company, Client, Contact,
Award, Mentor, Site, …) and which carries no combobox affordance. Per
`general-dry-one-shot-architecture` §7 the fix is an FK-backed selector against the app that
owns the entity — not a new create form in R80.4.

**This wants an eye before it wants a fix.** R80.4 has exactly one user-facing route (its
`main.tsx` routes `/`, `/auth/callback`, `/auth/login` and sends everything else to
NotFound), and the two inputs are inside the charge calculator, where a free-text label may
be the correct affordance for a scenario the user is modelling rather than a record they are
creating. The probe cannot tell those apart; whoever picks this up should name which entity
each input is standing in for and whether R80.4 is the owning app for it.

Stated because a silent skip is not a pass: this is the **only** FAIL class R80.4 returned
across all 8 cells. V-C1 pure endpoints, V-C2 gradient, V-C3 clipped headings, V-C7
elevation, V-C9 rendered junk and V-C10 layout/contrast were all clean, with 0 console
errors and 0 HTTP 4xx/5xx. R80.4 has no canvas, so `canvasColumns` is `notApplicable` rather
than UNKNOWN there.

Instrument control ran in every cell (a `#ffffff` and an `oklch(1 0 0)` surface must both be
flagged, a `#bbbbbb`-on-white pair must be reported at ~1.9:1, and the sanctioned near-white
`oklch(0.982 0.002 248)` must **not** be flagged): bit in 168 of 168 cells of the run.

Found by the SHIP lane while enumerating every remaining blocker on bsuite#3119. Reported,
not fixed.
