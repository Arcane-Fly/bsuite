# Column-count control is inert wherever the container is under 1200px (/settings is 1080px)

https://github.com/GaryOcean428/crm7/issues/2429

Snapshot updatedAt: 2026-09-04T15:18:14Z. Open at capture; re-read live.

Measured on the promotion candidate (d.crm.crm7.app at `fbd887c`), signed in, in the page editor on `/settings` at a 1440px viewport.

The column-count control is reachable and accepts input: the four-click editor path lands on `input[aria-label="Column count"]`, and setting 12, 6, 4 and 2 each reads back correctly. The rendered layout does not respond. Holding every reading until two samples 1.5s apart agreed, all four presets produce **one identical layout**, with card width pinned at 531px in every case.

The container is the reason and it is worth stating precisely: at a 1440px viewport the `/settings` content container measures **1080px**, and the control only rescales the `lg` breakpoint, which needs 1200px. So this is the documented "inert below a 1200px container" condition, now confirmed by interaction rather than inferred. The same control does act elsewhere — presets give distinct layouts on `/dashboard` at a wider container.

Two earlier passes disagreed with each other here because I read the layout before it settled; a short settle produced "4 columns gives fewer columns than 2", which is an artifact and not a real observation. Only the agreement-held readings above should be quoted.

The user-facing consequence is that on any page whose container is under 1200px, a control that visibly accepts a value silently does nothing. Either it should rescale the active breakpoint rather than only `lg`, or it should say it does not apply at this width. Pre-existing and outside the current promotion's scope.
