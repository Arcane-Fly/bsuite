# [P3] 352 localStorage call sites across 79 files — centralising makes the auth forbidden-pattern rules lintable

https://github.com/GaryOcean428/crm7/issues/1644

Snapshot updatedAt: 2026-08-24T03:28:37Z. Open at capture; re-read live.

**Source:** operator full-spectrum review, 2026-08-11 (Tier 5.1).

## Finding

**352 `localStorage` references across 79 files**, including auth tokens and offline caches.

## The part that makes this more than tidiness

`AUTH_CANONICAL.md` and `CLAUDE.md` carry a hard forbidden-pattern list for auth storage: no `cookieStorage`, no `domain=.crm7.app`, no `storageKey: 'business_suite_auth'`. Today that rule is enforced by **review and memory**. With 352 scattered call sites, nothing mechanically prevents the next one.

**Centralising behind one typed module makes the auth rules lintable** — a single chokepoint can be asserted in a contract test, and a bare `localStorage.setItem` outside it becomes a lint error. That converts a doctrine into a gate, which is the same move that worked for colours and a11y.

## Also solved by the same change

- **Namespacing** — no collisions between features.
- **Quota handling** — `localStorage` throws on quota exceeded and in Safari private mode. With 352 unguarded sites, at least some will be unhandled; that is an unhandled exception in a render path.
- **Schema versioning for offline caches** — a cache written by an old build and read by a new one is a shape mismatch with no migration story. This codebase has just been bitten twice by a *type* that disagreed with its data (crm7#1595); a persisted cache is the same hazard with a longer memory.
- **SSR/test safety** — one place to guard `typeof window === 'undefined'`.

## Approach

1. Inventory the 352 by purpose: auth, user preference, offline cache, UI state, one-off.
2. Write the typed module with namespacing, quota handling, JSON safety, and a version tag per cache key.
3. Migrate by category, auth first — it is the smallest group and the highest stakes.
4. **Then add the lint rule**, and only then. A rule added before the migration is red on day one and gets switched off by day two.
5. Keys already in use must be read at their existing names or users lose state on deploy. Plan the read-old/write-new window explicitly.

## Note
`crm7-has-completed-onboarding` is one of these keys and is load-bearing for e2e (seeded via `addInitScript` to suppress the onboarding wizard). Renaming keys will break test harnesses that seed them — grep the e2e suite before changing any name.

- **Equivalence target**: existing users keep their stored state across the deploy (read-old/write-new proven with a fixture), and a bare `localStorage` call outside the module fails lint
