# Award rates page shows no wages, mislabeled columns, and forces hand-coded JSON import instead of pulling from R8

https://github.com/GaryOcean428/crm7/issues/2055

Snapshot updatedAt: 2026-08-26T12:24:02Z. Open at capture; re-read live.

Two findings on the same data path: crm7's award-rates surface doesn't display or import correctly, and the intended source (R8) is not actually wired up as the source.

## What a user cannot do

- At `crm.crm7.app/payroll/award-rates`: **no wages are visible**, the period column just says "percent" instead of a real label, and there's no description shown for the row. Operator: "No wages are visible" (note.007).
- At `d.crm.crm7.app/charge-rates/import-r8`: the **import UX forces the user to hand-code** the input, and **R8 itself doesn't export in the format the importer expects** — it should be possible to pull straight from R8 instead of hand-authoring JSON. Operator: "This is horrible UX, its forcing the USER to code again, and r8 doesnt export like this. It should be able to pull in from R8." (note.069)

## Why these are one issue

Both are symptoms of the same missing link: crm7's award-rate display and import paths are not actually reading from R8's computed rate data (see also bsuite#1684, the architectural ruling that Charge Calculations are R8-owned by doctrine but authored in crm7 — this is a second, independent instance of the same drift, on award rates rather than charge rates).

## Done means

- The award-rates page shows real wage figures with a correctly labelled period column and a visible description per row.
- Importing a rate from R8 requires no hand-coded JSON — either a direct pull-from-R8 action, or an export format from R8 that this importer consumes without transformation.
