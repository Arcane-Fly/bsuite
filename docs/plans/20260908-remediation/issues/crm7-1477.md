## The diagnosis, corrected

The working hypothesis was that `/settings/data` and `/admin/data` were merely badly *named*. **That is refuted.** The operator opened both. The actual defect:

**Neither page ever shows you your data.** Both open on an empty **"Choose an entity"** dropdown. To get anywhere you must already know which of 84 entities you want, pick it blind, and then either upload a *file* (`/settings/data`) or build a *query* (`/admin/data`).

`/settings/data` is an import wizard. `/admin/data` is a query console. **Airtable opens showing you a table; these open showing you a form.** No rename fixes that.

## Scoreboard (verified live 2026-08-08)

| Measure | Value |
|---|---|
| `data_change_sets` (every bulk edit ever) | **0** |
| Saved builder views | **0** |
| Grid columns shipped `editable: true`, anywhere in six apps | **0** |

The write engine, the read engine (joins/GROUP BY/aggregates), the catalogue (84 entities / 1,208 fields / 124 joins) and a virtualised grid with TSV paste and undo **all exist**. The plumbing has never carried water.

## Scope

Built **into** `/settings/data` and `/admin/data` — **not a new `/data` route** (crm7 already has six "data"-named destinations; three collide).

- **T3.0 — prerequisite.** Per-field writability opt-in list. 11 of 13 active memberships are owner/admin, so shipping an editable grid before the permission product means every non-guest can edit every catalogued entity in their tenant.
- **T3.1 — findability.** Entity search; descriptions for the six ambiguous "Assessment" entities (only 23 of 84 have any description); business-language domain headings; remove the user-visible label "Documents (legacy)".
- **T3.2 — one entity end-to-end**, developer-tier only: grid, inline edit, add row, undo, on the repaired write path. This is the slice that moves `data_change_sets` off zero.
- **T3.3 — filter/sort with a real operator picker.** The engine supports `eq/neq/gt/gte/lt/lte/in/isNull/isNotNull`; the UI exposes none of them — it is one bare text input per column. Foreign-key values need an entity picker so nobody types a UUID.
- **T3.4 — saved views extending `report_configs` (`report_type='builder_view'`).** Do **not** create a second table; the existing one is live, RLS'd and has 0 rows.
- **T3.5 — extend to further entities.**

## Acceptance

Across **three structurally different entities** — one with a join, one with a PII-gated field, one plain — inline-edit and commit, undo from the UI, save a view and reload it, and paste multiple rows from Excel. Deployed build, signed in as a real account, then verified in SQL. **One cell on one entity is explicitly not acceptance** — that test can be passed today by a page nobody uses.

T3.1 separately: find the entity behind a *business phrase* without knowing the table name.

Blocked by: T2 (write-path repair).
