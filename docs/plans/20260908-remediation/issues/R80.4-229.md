# Every headline figure in the charge calculator is hardcoded and does not recompute from the selected award

Snapshot updatedAt: 2026-08-26T12:23:26Z. Open at capture; re-read live.

**Operator's overall verdict, this pass:** "Honestly - what is this shit: https://r8.crm7.app/ This is aweful" (note.043)

This is the R8 regression cluster bsuite#1967 (EPIC, D-67 to D-73) already named as "the largest block in the notes, almost entirely unfiled" — 16 findings from the 2026-08-26 test pass, all one root cause: **the calculator's outputs are disconnected from the award/classification/employment-type selection and show fixed demo values instead.**

## What a user cannot do

Select any award other than the one the demo was built against, and get correct numbers back. Every one of these was tested against a real award selection and failed:

| Card / field | What's shown | What should happen | Finding |
|---|---|---|---|
| Apprentice % of Standard Rate | Always $29.54 | Recompute per selected award (e.g. plumbing should show the plumbing award's rate, not building & construction's) | note.056 |
| Wages per apprenticeship year | Always Yr1 $14.725 / Yr2 $17.67 / Yr3 $20.615 / Yr4 (fixed) | Recompute per award | note.057 |
| MA000036 penalty table | Shows MA000020's clause references | MA000036 has no penalty table of its own wired in | note.059 |
| Apprentice share % | Always 100% | Should pull the real award percentage | note.062 |
| Award allowances | Always Building & Construction | Should reflect the selected award | note.063 |
| MA000036 trade selector | Does not exist | MA000036's trade list, allowance bands and clauses are all MA000020's | note.066 |
| Shift loading / industry allowance | Wrong for the sector combination tested | Should match the actual sector | note.068 |
| Standard Rate card, Apprentice %, Source | Don't update at all when the award selection changes | Full reactivity to award change | note.077 |
| "Adult" classification | Selecting it doesn't change the wages card | Should change the wage figures shown | note.126 |
| Apprentice %/standard rate pre-population | Not pre-populated from MAPD by employment type, despite the award text already containing these percentages | Pre-populate, flag per-financial-year recheck | note.096 |

## Related integration and logic defects, same page

- **Award selection doesn't sync between cards** — selecting an award in the "Award, Trade & Qualification" card doesn't populate the Fair Work MAPD card (note.075, repeat_offence=true — operator has raised this before).
- **Fairwork MAPD search throws a JSON parse error**: `Unexpected token '<', "<!doctype "... is not valid JSON` — the endpoint is returning an HTML error page instead of JSON (note.093).
- **No option for commercial construction sector**, which shares residential hours/penalty conditions but different pay rates (note.073, repeat_offence=true).
- **Payroll-tax exemption on suspended contracts** — the exemption runs only while a contract is registered; WA withdraws it while suspended, and the calculator doesn't reflect this (note.060).
- **Unclear how to zero out payroll tax** for exempt apprenticeships (note.065).
