# Placement create hard-blocks on missing host capacity assessment — create first, FO safety/capacity via workflow

https://github.com/GaryOcean428/crm7/issues/2581

Snapshot updatedAt: 2026-09-08T05:23:20Z. Open at capture; re-read live.

## Problem
`/placements/create` calls `assertHostCapacityForPlacement` and **returns without insert** when there is no completed `host_capacity_assessments` row for the host (`ok: false`, toast \"Host capacity required\").

Operators (incl. FutureBuild) experience this as a **site safety / capacity blocker** that prevents creating placements at all.

## Desired product behaviour
1. **Allow creating the placement** (the assignment can exist without a completed capacity assessment).
2. **Workflow / task**: assign FO **site safety inspection / capacity assessment** and schedule it (site_visits / capacity assessment screens).
3. Compliance gates may still apply at **status transitions** (e.g. moving to active on-site) if GTO Std 1.3 requires evidence — not at draft/create.

## Evidence
- Gate: `src/lib/hostCapacityGate.ts` — `MISSING` → `ok: false`
- Caller: `src/pages/placements/create.tsx` ~394–403 hard return
- Capacity UI exists at `/hosts/capacity-assessment` but is poorly discoverable
- FutureBuild (live client — do not seed fake assessments): 8 placements already exist; **new** creates against hosts without completed capacity are blocked

## DoD
- [ ] Create placement succeeds without a completed capacity assessment (toast may warn; must not hard-stop)
- [ ] Missing capacity still creates a **follow-up work item** (workflow run or FO task) to schedule capacity/safety inspection — not silent skip forever
- [ ] Unsuitable host still blocks create (or blocks only activate — product call; default: block activate, warn on create)
- [ ] Tests updated in `hostCapacityGate.test.ts` + create flow
- [ ] No production data writes / no fabricated FutureBuild capacity rows
- [ ] Registries if surface changes

## Out of scope
- Seeding capacity assessments for any live tenant
- Weakening unsuitable-host rules without an explicit product ruling

## September 8 operator remediation clarification

Preserve the distinction between saving a draft placement and authorizing a placement to commence. The notes request scheduling the required safety/capacity assessment through a workflow, not inventing a passed assessment to bypass validation.

- [ ] Save an incomplete draft with its real status and existing context; explain prerequisites at the actual activation/commencement transition.
- [ ] Offer to create the needed inspection/assessment inline, prefill host/person/site/placement, assign an eligible officer and due date, and attach its workflow/run to the placement.
- [ ] Retry creates one linked assessment/task; declined or failed scheduling preserves the placement draft and clearly shows the remaining prerequisite.
- [ ] Assessment result updates eligibility only through the canonical authorized transition; test unsafe, missing, expired and valid results independently.
- [ ] Preserve rate calculation/quote context and existing records; no fake green safety rows, hidden server bypass or unconditional default approval.
- [ ] Verify create → schedule → assessment → allowed/denied activation and edit/reload from deployed UI.
