# Notifications are unreachable: no entry point in the shell, and no deep link on the rows

https://github.com/GaryOcean428/crm7/issues/2428

Snapshot updatedAt: 2026-09-04T15:24:18Z. Open at capture; re-read live.

Measured on the promotion candidate (d.crm.crm7.app at `fbd887c`), signed in as `braden@braden.com.au`.

`/notifications` is built, returns 200, and renders real data — "Total 2, Unread 2", two genuine forwarded emails with title, message, priority and date. It is also unreachable and inert, in two independent ways.

**No entry point exists anywhere in the application shell.** Enumerating every anchor in the shell for `notif` in either the text or the href returns zero. The header carries Toggle Sidebar, CRM7, Edit page, Switch to dark theme, the org name and User menu — no bell. The user menu opens with no notifications entry. The only way a person reaches this page is by typing the URL.

**The rows do not link to anything.** Inside `main`, the anchor count is zero. The only controls are "Mark All Read" and a priority filter. So a notification about a specific thing cannot be opened to reach that thing — the deep link does not exist, rather than being broken.

`/settings/notifications` returns HTTP 200 while rendering "404 - Page Not Found", so anything that guesses that path fails silently rather than redirecting.

This is the dead-route class, and the standing rule is that a dead route is unbuilt work: find the spec and build it out, never delete it. Two pieces are owed — an entry point with an unread count, and a per-notification destination. Neither is in the current promotion's scope, which is why this is filed rather than blocking it.
