# Publish @bsuite/workflow-canvas and delete the crm7 contract duplication

https://github.com/GaryOcean428/crm7/issues/2302

Snapshot updatedAt: 2026-09-01T12:08:47Z. Open at capture; re-read live.

## Blocked by

`@bsuite/workflow-canvas` is **not published to npm** (`npm view @bsuite/workflow-canvas` → 404, checked 2026-09-01). crm7 resolves every `@bsuite/*` dependency from the registry, so adding it would break `pnpm install` and CI.

## The debt this forced

The graph contract that `packages/workflow-canvas/src/schemas.ts` OWNS is currently re-declared in two other places:

| Copy | Why it could not import the package |
| --- | --- |
| `crm7/src/lib/workflows/workflowGraph.ts` | package unpublished; also a React package with an `@xyflow/react` peer, and the first caller is `api/ai/chat.ts` on Vercel Edge — a chat endpoint must not bundle a canvas renderer to describe a process |
| `business-suite-unified/supabase/functions/feature-builder-ai/workflow-graph.ts` | an edge function cannot import from `src/`, let alone `packages/` |

Three copies of one contract will drift. When they do, the symptom is not a build error — it is a workflow that saves and then cannot be reopened, which reads to the user as a document that vanished.

## What holds it together in the meantime

- `crm7/src/lib/workflows/workflowGraph.contract.test.ts`
- `business-suite-unified/src/lib/feature-builder/__tests__/edge-fn-contract.test.ts`

Both assert the field-level bounds and the loose-object envelope against the package's source, and both **skip loudly** (never silently green) when `packages/workflow-canvas` is absent from the checkout.

## Acceptance criteria

1. `@bsuite/workflow-canvas` is published, and crm7 depends on it at a pinned version.
2. `crm7/src/lib/workflows/workflowGraph.ts` keeps only the outline→graph builder and the layout constants; its schema half is deleted and imported from the package instead.
3. `crm7/src/lib/workflows/workflowGraph.contract.test.ts` is deleted — it exists only to guard the duplication.
4. The edge-function copy stays (an edge function genuinely cannot import from `packages/`), and `edge-fn-contract.test.ts` stays with it.
5. `pnpm typecheck` and the workflow test suites pass in crm7 after the swap.

## Validation loop

§9.1 output-equivalence. **Equivalence target:** `buildWorkflowGraph` must produce a byte-identical graph for the fixture outline in `workflowGraph.test.ts` before and after the swap, and `serialiseGraph` must accept and reject exactly the documents listed in the contract test's `accepted`/`rejected` tables.
