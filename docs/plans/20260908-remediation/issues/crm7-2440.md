# resolveTenantSelection: a localStorage tenant is honoured when the server pin is NULL — that is a guess for a multi-tenant user, and it should ask

https://github.com/GaryOcean428/crm7/issues/2440

Snapshot updatedAt: 2026-09-06T09:42:32Z. Open at capture; re-read live.

Raised by the PI-run enforcer while gating crm7#2436, as a residual outside that PR's scope.

`resolveTenantSelection` honours a **localStorage** tenant at its third step when the server pin (`profiles.current_tenant_id`) is NULL. For a person with two or more memberships and no server pin, that step picks the organisation the browser last remembered and proceeds. That is a guess: NULL from the server means "they have not chosen", and the fail-closed rule is that a NULL meaning unknown is never read as a choice. The browser's memory is not the person's decision — it can be a different person on a shared machine, or a membership since revoked, or simply stale.

The consistent behaviour is the one `useTenantConfirmation` already implements for the confirm path: when there is no server pin and more than one membership, **ask**, and write the pin through `set_current_tenant` on the answer. localStorage can remain a hint for which option to preselect; it must not be the selection.

Pre-existing, not introduced by #2436; recorded here so the class has an owner. Related: the resolution order in `acting_scope_tenant_id()` (acting-as row → profile pin → sole membership → NULL) and `bsuite_correction` records on deterministic guesses.
