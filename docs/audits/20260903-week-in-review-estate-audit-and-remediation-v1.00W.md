Terms used throughout, glossed once:

| Term | Meaning here |
|---|---|
| gitlink | the parent repository's recorded pointer to a submodule commit; if it lags the app's own `main`, the parent describes an older app than the one in production |
| ratchet | a check that forbids a count getting worse; it never forces the count down, so old debt can sit at the same number forever |
| RLS | row-level security, the Postgres rule that decides which rows a tenant's user may see; the hard wall behind every app |
| SECURITY DEFINER | a database function that runs with its owner's rights rather than the caller's; a mistake in one is a privilege hole |
| pg_cron | the scheduler inside the database that runs jobs on a timer |
| lockfile | the file that pins the exact package versions an app installs; a package "reaches" an app only when its lockfile resolves the new version |
| DoD, D1 to D8 | the definition of done gate: D1 to D7 prove a change is wired and evidenced, D8 proves a person can use it |
| MCP | Model Context Protocol server, a tool an agent can call (GitHub, Supabase, Vercel, memory) |
| OIDC trusted publishing | publishing a package with a short-lived identity token instead of a stored secret |
| SHA | the identifier of one commit |
| pgTAP | database tests that run inside Postgres |
| PKCE, JWKS | the two pieces of the sign-in handshake: a one-time code proof, and the published keys that let an app check a token without asking the server |
| CPaaS | a messaging provider you send SMS through (Mobile Message here) |
| RPC | a database function the app calls by name |
| ADR | an architecture decision record, a dated document that fixes one design choice |
| TGA, AVETMISS, STP | training.gov.au (the national training register), the national VET data standard, and Single Touch Payroll (the ATO's payroll reporting) |
| MCPP | the Microsoft partner account a verified-publisher badge needs |
| PostgREST | the layer that turns database tables into the API the apps call |
| DML | data rows (inserts and updates), as opposed to table definitions |

Evidence rules: every finding cites a file and line, PR or issue number, memory key, thread timestamp, SQL result or URL. Counts are stated with the command that produced them. Findings are classes with a sibling count and the method used to enumerate. Where a lane could not verify, the item is marked UNVERIFIABLE with what would verify it. Repo-wide measurements exclude `.claude/worktrees`, `node_modules`, `dist`, `.vercel` and `public`. Lane findings files are retained in the session scratchpad and summarised, not copied, here.

Three limits. First, thread extracts hold the operator's messages and machine echoes, not the agents' replies; what an agent did next is reconstructed from the operator's subsequent messages and stop-hook verdicts. Second, the checked-out working tree had two submodules on feature branches and three detached; code lanes recorded the SHA they measured rather than moving anything. Third, the external-model lanes ran with a 200k-token window and compaction; each was told to write its file incrementally so nothing was lost to a cut-off, and each file states what it covered.
